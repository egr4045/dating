# Dating App — Review: UI/UX & Admin Panel

_Дата: 2026-04-11_

---

## Часть 1: UI/UX — что улучшить и что добавить

### Визуал и дизайн-система

- **Тёмная тема** — сейчас только светлая. Добавить CSS-переменные для dark mode, переключатель в настройках. Особенно важно для вечерних пользователей.
- **Skeleton loaders** — почти везде при загрузке показывается пустота. Нужны shimmer-заглушки (карточки, профиль, история).
- **Micro-анимации** — переходы между шагами онбординга резкие. Добавить `transition: transform 0.3s ease` при смене шага и при появлении карточек.
- **Haptic feedback** — при свайпе (like/nope) нет вибрации. Добавить `navigator.vibrate(50)` для ощущения отклика на мобиле.
- **Страница ошибок** — если API недоступен, пользователь видит пустой экран или "undefined". Нужен fallback UI с кнопкой "Попробовать снова".

### Онбординг

- **Предпросмотр карточки профиля** — на финальном шаге показать, как твой профиль выглядит для других (превью QuestCard с твоими данными).
- **Прогресс-бар** — текущий показывает точки, но не число шагов. Добавить "Шаг 3 из 7".
- **Пропуск видео-верификации слишком незаметен** — многие пользователи могут не заметить кнопку "Пропустить". Это может влиять на качество базы. Либо сделать верификацию обязательной, либо явно объяснить последствия пропуска.
- **Валидация возраста** — возраст 16 лет разрешён, но нет подтверждения. Стоит добавить предупреждение или ограничить до 18+.
- **Автосохранение черновика** — если пользователь вышел на середине онбординга, данные теряются. Сохранять `localStorage` на каждом шаге.

### Дашборд / Свайп-лента

- **Возможность отменить последний свайп** — кнопка "Отмена" (undo). Стандарт для подобных приложений.
- **Предпросмотр события** — по нажатию на карточку (не свайп) открывать детали события: полное описание, адрес на карте, больше фото.
- **Фильтры — расширить** — сейчас только пол и возраст. Добавить: категория события (активности / игры / онлайн), цена (до X руб.), дата.
- **Pull-to-refresh** — на мобиле стандартное действие для обновления ленты. Сейчас есть кнопка "обновить", но нет жеста.
- **Пустой стейт** — при отсутствии событий показывается простое сообщение. Сделать его мотивирующим: объяснить, что ещё будут события, предложить изменить фильтры.
- **Индикатор количества оставшихся карточек** — "Осталось 3 события" помогает понять ситуацию.

### Чат / Активный матч

- **Статус прочтения** — сообщения отправляются и принимаются, но нет галочек "прочитано". Уже есть `markAsRead` в socket, но в UI не отображается.
- **Отправка изображений** — сейчас только текст. Хотя бы базовая поддержка emoji-реакций или стикеров.
- **Индикатор набора текста** — "Партнёр печатает..." — стандартная фича для чатов.
- **Уведомление о новом сообщении** — если пользователь свернул приложение, нет браузерного push-уведомления (есть только Telegram-бот). Добавить `Notification API` или badge на вкладке.
- **Таймер до разблокировки кнопок** — кнопки "Завершено / Не получилось" заблокированы 15 минут. Но таймер показывается только как текст. Добавить визуальный прогресс-бар/кольцо.
- **Подтверждение при завершении** — нажатие "Не получилось" — необратимое действие, но нет диалога подтверждения.

### Шедулинг (выбор даты)

- **Отсутствие часового пояса** — `datetime-local` берёт локальное время браузера. Если партнёры из разных городов, это приведёт к путанице.
- **Наглядность слотов** — сейчас предлагается ввод `datetime-local`. Лучше показать мини-календарь с маркерами доступности.
- **История предложений** — в случае многократных отклонений/перепредложений нет лога. Пользователь не понимает, сколько раз уже отклоняли.

### Настройки и профиль

- **Нет страницы "Мой профиль"** — пользователь не видит, как выглядит его карточка для других. Добавить кнопку "Предпросмотр профиля".
- **Смена фото** — в настройках не показана опция изменить фото (только просмотр). Нужна кнопка редактирования.
- **Удаление аккаунта** — нет такой опции. Требование GDPR/ФЗ-152 для российского рынка.
- **Репутация без объяснения** — цифра репутации видна, но нет tooltip/пояснения: за что начисляется, как не потерять.
- **Статус бана непонятен** — если пользователь забанен, он видит экран, но не знает, почему и навсегда ли.

### История

- **Фильтрация и сортировка** — нет возможности фильтровать по статусу (только завершённые, только отменённые) или сортировать по дате.
- **Детали матча недоступны** — в истории показаны карточки матчей, но нет перехода к деталям (партнёр, событие, дата).

### Прочее / Технические UX-вещи

- **Нет offline-режима** — при потере сети приложение молча падает. Добавить `service worker` или хотя бы toast "Нет соединения".
- **SEO/метатеги** — приложение открывается в Telegram WebApp, но при шаринге ссылки нет og:image / og:title.
- **Accessibility** — нет `aria-label` на иконках, нет поддержки keyboard navigation. Минимум — alt у изображений и labels у форм.
- **Локализация** — текст смешан: часть на русском (интерфейс), часть на английском (технические строки). Привести к единому языку.

## Часть 2: Проверка админки

### Аналитика — найденные баги

#### BUG #1: `swipe_nope` никогда не отправляется
**Файл:** `frontend/src/components/Dashboard.vue`

В коде трекается только `swipe_like`, но нет `track('swipe_nope', ...)`. При этом бэкенд в `admin.service.ts` пытается посчитать `totalSwiperNopes` — он всегда будет **0**. Это объясняет "странные данные": колонка нопов пуста, конверсия завышена.

```ts
// Dashboard.vue — только это есть:
track('swipe_like', { questId })
// Нет: track('swipe_nope', { questId })
```

#### BUG #2: Конверсия считается неправильно
**Файл:** `backend/src/admin/admin.service.ts`

```ts
conversion: totalSwipeLikes > 0
  ? ((newMatches / totalSwipeLikes) * 100).toFixed(1) + '%'
  : '0%',
```

Делитель — только лайки, а не все свайпы (лайки + нопы). Правильный знаменатель: `totalSwipeLikes + totalSwiperNopes`. Сейчас при 50 лайках и 10 матчах показывается 20%, хотя реальная конверсия с учётом нопов меньше.

#### BUG #3: Верификация видео — фронтенд vs бэкенд
**Файлы:** `backend/src/admin/admin.service.ts`, `frontend/src/components/admin/AdminUserDetail.vue`

В AdminUserDetail показывается статус `videoVerified` пользователя, но **нет бэкенд-эндпоинта** для его изменения. То есть администратор видит, верифицирован ли пользователь, но не может нажать кнопку "Верифицировать" — её либо нет в UI, либо она ни к чему не подключена.

```ts
// Отсутствует в admin.service.ts:
async verifyUser(userId: number) {
  return this.prisma.user.update({
    where: { id: userId },
    data: { videoVerified: true },
  });
}
// И соответствующий PATCH /admin/users/:id/verify в controller
```

#### BUG #4: Top Users возвращает только ID, без имён
**Файл:** `backend/src/admin/admin.service.ts`

`getTopUsers()` делает `groupBy(['userId'])` по таблице `analyticsEvent`, возвращая только `{ userId, count }`. Имена, фото, email пользователей не включаются. Фронтенд вынужден делать отдельные запросы или показывать пустые строки.

### Что работает нормально

- Авторизация в админке (`x-admin-token` хедер) — работает, NestJS автоматически приводит заголовки к нижнему регистру.
- Список пользователей, матчей, чатов — загружаются корректно.
- Сводная статистика за период (`/admin/analytics/summary`) — работает, но данные искажены из-за BUG #1 и #2.
- Пагинация событий (`/admin/analytics/events`) — работает.
